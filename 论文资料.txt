## 方法二：多层启发式 + 多目标 Pareto 分析

方法二不是只求一个最优解，而是先用多组权重跑出一批调度方案，再从中筛出 Pareto 非支配解。

---

## 1. 基本符号

设：

- `i`：任务编号
- `r`：执行区域
- `t`：小时
- `s_i`：任务 `i` 的开工时间
- `d_i`：任务持续时间
- `g_i`：任务 GPU 需求
- `q_i`：任务来源区域
- `l_i`：任务最大允许时延
- `p_i`：任务单位 GPU 功率

任务功率：

```text
P_i = g_i × p_i
```

任务时间占用重叠系数：

```text
h_{i,t} = max(0, min(t+1, s_i+d_i) - max(t, s_i))
```

---

## 2. 可行域公式

### 2.1 区域可行性

任务 `i` 只能调度到满足时延约束的区域：

```text
R_i = { r | NetworkLatency(q_i, r) ≤ l_i }
```

### 2.2 时间可行性

实时推理任务：

```text
s_i = ArrivalHour_i
```

批量推理和训练任务：

```text
ArrivalHour_i ≤ s_i ≤ LatestFinishHour_i - d_i
```

并且：

```text
s_i + d_i ≤ 2406
```

---

## 3. 资源约束公式

### 3.1 GPU 容量

```text
GPU_Used(r,t) = Σ_i Σ_s g_i × h_{i,t} × x_{i,r,s}
```

约束：

```text
GPU_Used(r,t) ≤ Available_GPU(r)
```

### 3.2 AI IT 负荷

```text
AI_IT_Load(r,t) = Σ_i Σ_s P_i × h_{i,t} × x_{i,r,s}
```

总 IT 负荷：

```text
IT_Load(r,t) = NonAI_IT_Load(r,t) + AI_IT_Load(r,t)
```

设施负荷：

```text
Total_Load(r,t) = IT_Load(r,t) × PUE(r)
```

### 3.3 功率约束

```text
IT_Load(r,t) ≤ Max_IT_Power_MW(r)
```

```text
Total_Load(r,t) ≤ Max_Facility_Power_MW(r)
```

---

## 4. 多目标评分公式

方法二的核心是把每个候选方案 `(i,r,s)` 评成一个分数：

```text
Score(i,r,s)
= α · Cost(i,r,s)
+ β · Carbon(i,r,s)
+ γ · Latency(i,r)
- δ · RenewableBenefit(i,r,s)
+ μ · Congestion(i,r,s)
```

其中：

- `Cost(i,r,s)`：新增运行成本
- `Carbon(i,r,s)`：新增碳排放
- `Latency(i,r)`：网络时延
- `RenewableBenefit(i,r,s)`：新能源消纳收益
- `Congestion(i,r,s)`：拥塞惩罚

---

## 5. 成本与碳排公式

设施侧新增负荷：

```text
ΔLoad(r,t) = P_i × h_{i,t} × PUE(r)
```

直接消纳新能源：

```text
UsedRenewable(r,t) = min(ΔLoad(r,t), AvailableRenewable(r,t))
```

电网购电：

```text
GridPurchase(r,t) = max(0, ΔLoad(r,t) - AvailableRenewable(r,t))
```

成本：

```text
Cost(i,r,s) = Σ_t GridPurchase(r,t) × ElectricityPrice(r,t)
```

碳排：

```text
Carbon(i,r,s) = Σ_t GridPurchase(r,t) × CarbonIntensity(r,t)
```

新能源收益：

```text
RenewableBenefit(i,r,s) = Σ_t UsedRenewable(r,t)
```

---

## 6. 拥塞惩罚公式

GPU 利用率：

```text
u_GPU(r,t) = GPU_Used(r,t) / Available_GPU(r)
```

功率利用率：

```text
u_Power(r,t) = Total_Load(r,t) / Max_Facility_Power_MW(r)
```

拥塞惩罚可写为：

```text
Congestion(i,r,s) = max(u_GPU(r,t), u_Power(r,t))
```

也可以用超过阈值的部分：

```text
Congestion(i,r,s)
= max(0, u_GPU(r,t)-ρ) + max(0, u_Power(r,t)-ρ)
```

---

## 7. Pareto 支配关系

对两个方案 `A` 和 `B`，若：

```text
A 在所有目标上都不差于 B
且至少一个目标优于 B
```

则称 `A` 支配 `B`。

即：

```text
A ≺ B
```

非支配解集合就是 Pareto 前沿：

```text
ParetoFront = { x | 不存在 y 支配 x }
```

---

## 8. 多策略权重集

方法二不是只跑一组权重，而是跑多组：

```text
balanced
cost_first
carbon_first
renewable_first
latency_first
carbon_renewable
cost_carbon
load_balanced
```

每组权重对应一套：

```text
(α, β, γ, δ, μ)
```

例如：

### 综合策略
```text
α = 1.0
β = 500
γ = 2
δ = 100
μ = 100
```

### 成本优先
```text
α ↑, β ↓, γ ↓
```

### 低碳优先
```text
β ↑
```

### 新能源优先
```text
δ ↑
```

---

## 9. 方法二算法流程

### 算法 1：多层启发式调度

```text
输入：任务集、区域算力数据、网络时延、电力数据、功率映射
输出：多个策略的调度结果

1. 预处理任务：
   计算 d_i、P_i、Slack_i

2. 构造可行区域集 R_i：
   保留满足 NetworkLatency ≤ MaxLatency 的区域

3. 划分滚动窗口：
   例如 0-23, 24-47, ..., 2376-2399

4. 对每个策略 k：
   4.1 设置权重 (α_k, β_k, γ_k, δ_k, μ_k)
   4.2 对每个窗口：
       - 取当前窗口内任务
       - 对每个任务生成候选 (r,s)
       - 计算 Score(i,r,s)
       - 选最小分候选
       - 更新 GPU_Used、AI_IT_Load、Total_Load
   4.3 输出该策略的调度表和指标

5. 汇总所有策略结果
```

---

## 10. 算法 2：Pareto 筛选

```text
输入：所有策略的指标向量
输出：Pareto 前沿

1. 对每个策略计算：
   Cost, Carbon, Latency, RenewableUtilization,
   PeakGridPurchase, UnassignedCount

2. 构造目标向量：
   z = (Cost, Carbon, Latency, -RenewableUtilization,
        PeakGridPurchase, UnassignedCount)

3. 对任意两个策略 A,B：
   若 A 在全部目标上不差于 B，且至少一项更优，
   则删除 B

4. 剩余策略构成 Pareto Front
```

## 11. 论文里可写成的总公式

如果你想写成标准优化模型，可以写为：

```text
min  F(x) = [F1(x), F2(x), F3(x), F4(x), F5(x)]
```

其中：

```text
F1 = 总成本
F2 = 总碳排
F3 = 平均时延
F4 = -新能源利用率
F5 = 峰值购电
```

再通过权重法转成单目标：

```text
min Z = Σ_m w_m F_m(x)
```

然后通过不同 `w_m` 生成不同策略，再做 Pareto 分析。

## 12. 一句话总结

方法二的本质是：

```text
先用多层启发式在滚动窗口内生成多组可行调度方案，
再用 Pareto 非支配关系筛出多目标折中解。
```

如果你要，我下一条可以直接给你整理成**“论文正文版”**，就是能直接贴到建模论文里的那种。


方法一是：

```text
加权单目标 + 分时段滚动调度
```

它的完整流程可以按下面写进论文。

**1. 明确输入**

问题2输入包括：

```text
任务数据 workload_trace.xlsx
区域算力数据 GPU_information.xlsx
区域间网络时延 network_latency.xlsx
任务功率映射 power_mapping.xlsx
区域逐时电力数据 region_time_data.xlsx
```

对每个任务，已知：

```text
TaskID
TaskType
ArrivalHour
GPU_Demand
EstimatedDuration_min
SourceRegion
MaxLatency_ms
LatestFinishHour
```

对每个区域，已知：

```text
Available_GPU
Max_IT_Power_MW
PUE
Max_Facility_Power_MW
```

对每个区域每小时，已知：

```text
ElectricityPrice
CarbonIntensity
AvailableRenewable
NonAI_IT_Load_MW
```

**2. 任务预处理**

先把任务持续时间从分钟换成小时：

```text
d_i = EstimatedDuration_min_i / 60
```

任务功率由 GPU 需求和任务类型决定：

```text
p_i = GPU_Demand_i × GPU_Power(TaskType_i)
```

其中：

```text
AITraining        0.16 MW/GPU
BatchInference    0.10 MW/GPU
RealTimeInference 0.08 MW/GPU
```

然后确定任务的允许开工区间。

实时推理任务：

```text
s_i = ArrivalHour_i
```

批量推理和 AI 训练任务：

```text
ArrivalHour_i ≤ s_i
s_i + d_i ≤ LatestFinishHour_i
s_i + d_i ≤ 2406
```

**3. 构建滚动时间窗口**

把 `0-2399` 小时按固定窗口分段，比如每 24 小时一个窗口：

```text
第1个窗口：0-23
第2个窗口：24-47
第3个窗口：48-71
...
最后一个窗口：2376-2399
```

每次只处理当前窗口内到达的任务。

例如窗口 `τ` 包含：

```text
W_τ = { i | ArrivalHour_i ∈ [τ, τ+Δ-1] }
```

其中 `Δ` 是窗口长度，比如 24 小时。

同时设置向未来看的调度搜索范围：

```text
Lookahead = 72 小时
```

也就是当前窗口到达的弹性任务，可以在未来 72 小时内选择开工时间，但不能超过最晚完成时间。

**4. 生成候选方案**

对每个任务 `i`，生成候选方案：

```text
(i, r, s)
```

表示任务 `i` 在区域 `r`，从小时 `s` 开始执行。

先筛区域：

```text
NetworkLatency(SourceRegion_i, r) ≤ MaxLatency_i
```

不满足时延的区域直接剔除。

再筛开工时间：

实时任务：

```text
s = ArrivalHour_i
```

批量/训练任务：

```text
s ∈ [ArrivalHour_i, min(LatestFinishHour_i - d_i, 当前窗口起点 + Lookahead)]
```

然后检查该候选方案是否满足资源约束。

**5. 计算任务占用**

任务执行期间不可抢占、不可拆分，所以它从 `s_i` 连续运行到：

```text
f_i = s_i + d_i
```

如果任务跨多个小时，需要计算它在每个小时的重叠时长：

```text
Overlap(i,t) = 任务 i 在小时 t 内占用的小时数
```

于是任务对区域 `r`、小时 `t` 的 GPU 占用为：

```text
GPU_Demand_i × Overlap(i,t)
```

任务形成的 AI IT 负荷为：

```text
GPU_Demand_i × GPU_Power(TaskType_i) × Overlap(i,t)
```

**6. 约束条件**

候选方案必须满足以下硬约束。

每个任务只能调度一次：

```text
每个任务选择一个区域和一个开工时间
```

GPU 容量约束：

```text
Σ GPU_Demand_i × Overlap(i,r,t) ≤ Available_GPU_r
```

AI IT 负荷：

```text
AI_IT_Load(r,t)
= Σ GPU_Demand_i × GPU_Power(TaskType_i) × Overlap(i,r,t)
```

总 IT 负荷：

```text
IT_Load(r,t)
= NonAI_IT_Load_MW(r,t) + AI_IT_Load(r,t)
```

设施侧总负荷：

```text
Total_Load(r,t)
= IT_Load(r,t) × PUE_r
```

IT 功率上限：

```text
IT_Load(r,t) ≤ Max_IT_Power_MW_r
```

设施功率上限：

```text
Total_Load(r,t) ≤ Max_Facility_Power_MW_r
```

网络时延约束：

```text
NetworkLatency(SourceRegion_i,r) ≤ MaxLatency_i
```

完成时间约束：

```text
f_i ≤ LatestFinishHour_i
f_i ≤ 2406
```

实时任务约束：

```text
s_i = ArrivalHour_i
```

**7. 多目标转加权单目标**

问题2有多个目标：

```text
运行成本
碳排放
网络时延
新能源利用率
容量均衡
```

方法一把它们合成为一个加权目标函数。

对候选方案 `(i,r,s)` 定义综合评分：

```text
Score(i,r,s)
= α Cost(i,r,s)
+ β Carbon(i,r,s)
+ γ Latency(i,r)
- δ RenewableBenefit(i,r,s)
+ μ Congestion(i,r,s)
```

其中：

```text
Cost(i,r,s)
```

表示任务执行期间新增购电成本。

```text
Carbon(i,r,s)
```

表示任务执行期间新增碳排放。

```text
Latency(i,r)
```

表示任务从来源区域到执行区域的网络时延。

```text
RenewableBenefit(i,r,s)
```

表示该任务执行期间可额外消纳的新能源。

```text
Congestion(i,r,s)
```

表示区域 GPU 或功率资源接近上限时的惩罚。

这里新能源项前面是负号，因为新能源消纳越多越好。

**8. 成本、碳排和新能源估算**

对任务候选方案，先计算它在执行期间新增设施负荷：

```text
ΔLoad(r,t) = GPU_Demand_i × GPU_Power(TaskType_i) × PUE_r × Overlap(i,t)
```

如果当前时段还有新能源富余，则优先用新能源：

```text
RenewableBenefit(i,r,s)
= min(ΔLoad(r,t), RenewableSurplus(r,t))
```

新增电网购电：

```text
ΔGridPurchase(r,t)
= max(0, ΔLoad(r,t) - RenewableSurplus(r,t))
```

新增成本：

```text
Cost(i,r,s)
= Σ ΔGridPurchase(r,t) × ElectricityPrice(r,t)
```

新增碳排：

```text
Carbon(i,r,s)
= Σ ΔGridPurchase(r,t) × CarbonIntensity(r,t)
```

**9. 窗口内求解**

在每个滚动窗口内，对当前窗口的任务进行调度。

如果用 MILP 表达，可以定义：

```text
x_{i,r,s} = 1，表示任务 i 选择区域 r 和开工时间 s
x_{i,r,s} = 0，否则
```

窗口目标函数：

```text
min Σ Score(i,r,s) × x_{i,r,s}
```

约束：

```text
Σ_{r,s} x_{i,r,s} = 1
```

以及 GPU、IT功率、设施功率等约束。

如果用启发式 greedy 版本，则流程是：

```text
按 ArrivalHour 和 LatestFinishHour 排序任务
对每个任务生成候选方案
计算所有候选方案 Score
选择 Score 最小且满足约束的方案
更新 GPU 占用和 AI IT 负荷
进入下一个任务
```

**10. 滚动更新**

当前窗口求解完成后，把调度结果固定下来：

```text
更新 GPU_Used(r,t)
更新 AI_IT_Load(r,t)
更新 Total_Load(r,t)
```

然后进入下一个窗口。

已经安排的任务不再改变，后续窗口只能在已有占用基础上继续安排新任务。

这就是“滚动调度”的核心。

**11. 输出调度结果**

最终输出每个任务的调度方案：

```text
StartHour

NetworkLatency_ms
EstimatedCost_CNY
```


**12. 评价指标**

调度完成后，重新计算系统指标：

```text
总运行成本
总碳排放
平均网络时延
任务按时完成率
新能源利用率
弃电量
区域 GPU 平均利用率
区域 GPU 峰值利用率
系统峰值购电功率
```

新能源利用率：

```text
RenewableUtilization
= Σ UsedRenewable(r,t) / Σ AvailableRenewable(r,t)
```

总成本：

```text
TotalCost
= Σ GridPurchase(r,t) × ElectricityPrice(r,t)
```

总碳排：

```text
TotalCarbon
= Σ GridPurchase(r,t) × CarbonIntensity(r,t)
```

**13. 方法一总结**

方法一完整逻辑就是：

```text
先按时间窗口滚动处理任务；
每个任务生成可行的区域-开工时间候选方案；
用成本、碳排、时延、新能源和拥塞构造加权评分；
选择窗口内综合得分最低且满足硬约束的调度方案；
调度后更新资源占用和电力负荷；
最终计算系统成本、碳排、时延和新能源利用率。
```

论文里可以命名为：

```text
基于加权单目标的碳感知滚动窗口调度模型
```

或者：

```text
Weighted Carbon-aware Rolling Scheduling Model, WCRS
```


**方法一和方法二的核心区别**

```text
方法一：加权单目标 + 分时段滚动调度
方法二：多层启发式 + 多策略 Pareto 分析
```

方法二本质上是方法一的扩展：先用方法一生成多个不同权重下的调度方案，再进行 Pareto 筛选。

| 对比项 | 方法一 | 方法二 |
|---|---|---|
| 优化思想 | 多目标合成一个目标 | 同时生成多个折中方案 |
| 权重设置 | 只用一组权重 | 使用多组权重 |
| 输出结果 | 一个最终调度方案 | 多个策略方案 + Pareto 前沿 |
| 运行时间 | 较短 | 较长，约为多次方法一 |
| 模型复杂度 | 较低 | 较高 |
| 结果解释 | 简单直接 | 能分析多目标权衡 |
| 对权重敏感性 | 较强 | 可通过多策略减弱 |
| 适合用途 | 快速得到一个方案 | 做论文分析和策略比较 |
| 推荐定位 | 基础求解模型 | 综合分析模型 |

**一、方法一的流程**

方法一先固定一组权重：

```text
Score
= α·成本
+ β·碳排
+ γ·时延
- δ·新能源消纳
+ μ·拥塞惩罚
```

然后按时间窗口滚动调度：

```text
0-23
24-47
48-71
...
```

每个任务都执行：

```text
生成可行区域
生成可行开工时间
计算综合评分
选择评分最低的方案
更新GPU和功率占用
```

最后得到一套任务调度结果。

例如：

```text
任务1 -> RegionA，小时10开始
任务2 -> RegionD，小时15开始
任务3 -> RegionE，小时20开始
```

这套方案可能成本较低，但不一定是碳排最优或新能源利用率最高。

**二、方法二的流程**

方法二先设置多组权重：

```text
balanced
cost_first
carbon_first
renewable_first
latency_first
load_balanced
```

每一组权重都调用一次类似方法一的滚动调度算法，得到多个候选方案：

```text
方案1：成本优先
方案2：低碳优先
方案3：新能源优先
方案4：时延优先
方案5：综合权衡
```

然后统一计算每个方案的：

```text
总成本
总碳排
平均网络时延
新能源利用率
峰值购电
任务完成率
```

最后进行 Pareto 筛选。

如果方案 A 在所有指标上都不差于方案 B，并且至少有一个指标更好，那么方案 A 支配方案 B，方案 B 被删除。

剩余方案就是 Pareto 前沿。

**三、二者在结果上的区别**

方法一可能只得到：

```text
成本：较低
碳排：中等
时延：中等
新能源利用率：中等
```

方法二可能得到：

```text
成本优先方案：
成本最低，但碳排稍高

低碳优先方案：
碳排最低，但时延和成本略高

新能源优先方案：
新能源利用率最高，但跨区域迁移更多

时延优先方案：
时延最低，但成本和碳排可能增加
```

这样就可以告诉评委：

```text
不同目标之间存在冲突，不能同时达到各自最优；
Pareto前沿提供了多个可供决策者选择的折中方案。
```

**四、方法一的优点**

方法一适合快速求解，优点是：

- 运行速度较快；
- 代码结构简单；
- 参数少；
- 易于调试；
- 容易解释；
- 适合先验证任务调度是否可行。

缺点是：

- 权重有一定主观性；
- 只得到一个方案；
- 对权重选择比较敏感；
- 不能充分展示多目标冲突。

**五、方法二的优点**

方法二更适合比赛论文，优点是：

- 更符合多目标优化题意；
- 可以展示不同策略；
- 能得到 Pareto 前沿；
- 便于做敏感性分析；
- 可以避免只依赖一组主观权重。

缺点是：

- 要重复运行多次；
- 运行时间更长；
- 输出文件更多；
- 需要画 Pareto 图并解释；
- 如果各组权重差异太小，多个方案可能非常相似。

**六、论文中推荐的关系**

不要把它们写成两个互不相关的模型，最好写成递进关系：

```text
方法一：构造基础调度模型
方法二：在基础调度模型上改变权重，生成策略集合并进行 Pareto 筛选
```

论文结构可以写成：

```text
3.1 任务可行域构造
3.2 加权单目标滚动调度模型
3.3 多策略权重设计
3.4 Pareto 非支配解筛选
3.5 不同策略的调度结果比较
```

**七、最终建议**

如果只是想尽快得到一个可用结果：

```text
优先使用方法一
```

如果想让论文的多目标分析更完整：

```text
方法一跑基础方案
方法二跑多策略和 Pareto 前沿
```

最推荐的最终方案是：

```text
方法一作为基础调度算法；
方法二作为论文的增强分析方法。
```

简单说：

```text
方法一回答：怎样得到一个可行且较优的调度方案？

方法二回答：在成本、碳排、时延和新能源利用之间，
有哪些不同的折中方案，哪几种属于 Pareto 最优？
```
