## 一、队友提供了什么（一句话版）

- **方法一**：加权单目标 + 分时段滚动调度 → 得到一套可行且较优的调度方案（基础模型）。
- **方法二**：方法一的扩展——多组权重跑出多套方案 → Pareto 非支配筛选 → 得到多目标折中方案集。
- 两者写成递进关系：方法一是基础调度模型，方法二是多目标增强分析。

## 二、可直接写进论文的核心公式

### 2.1 任务基本量

- 任务持续时间（小时）：$d_i = EstimatedDuration\_min_i / 60$
- 任务功率：$P_i = g_i \times p_i$（$g_i$ 为 GPU 需求，$p_i$ 为单位 GPU 功率）
- 功率映射（队友给出，需与 power_mapping.xlsx 核对）：
  - AITraining：0.16 MW/GPU
  - BatchInference：0.10 MW/GPU
  - RealTimeInference：0.08 MW/GPU
- 重叠系数（任务 i 在小时 t 内的占用时长）：
  $h_{i,t} = \max(0,\ \min(t+1,\ s_i+d_i)-\max(t,\ s_i))$

### 2.2 可行域

- 区域可行：$R_i = \{ r \mid NetworkLatency(q_i, r) \le l_i \}$
- 实时任务：$s_i = ArrivalHour_i$
- 批量/训练任务：$ArrivalHour_i \le s_i \le LatestFinishHour_i - d_i$，且 $s_i + d_i \le 2406$

### 2.3 资源约束

- GPU 容量：$GPU\_Used(r,t) = \sum_i \sum_s g_i h_{i,t} x_{i,r,s} \le Available\_GPU(r)$
- AI IT 负荷：$AI\_IT\_Load(r,t)=\sum_i \sum_s P_i h_{i,t} x_{i,r,s}$
- 总 IT 负荷：$IT\_Load(r,t)=NonAI\_IT\_Load(r,t)+AI\_IT\_Load(r,t)$
- 设施负荷：$Total\_Load(r,t)=IT\_Load(r,t)\times PUE(r)$
- 功率上限：$IT\_Load(r,t)\le Max\_IT\_Power\_MW(r)$；$Total\_Load(r,t)\le Max\_Facility\_Power\_MW(r)$
- 完成时限：$f_i=s_i+d_i \le LatestFinishHour_i$，且 $f_i\le 2406$

### 2.4 综合评分（多目标转加权单目标）

$$Score(i,r,s)=\alpha\,Cost(i,r,s)+\beta\,Carbon(i,r,s)+\gamma\,Latency(i,r)-\delta\,RenewableBenefit(i,r,s)+\mu\,Congestion(i,r,s)$$

其中：
- 设施侧新增负荷：$\Delta Load(r,t)=P_i \times h_{i,t} \times PUE(r)$
- 新能源直接消纳：$UsedRenewable(r,t)=\min(\Delta Load(r,t),\ AvailableRenewable(r,t))$
- 新增购电：$GridPurchase(r,t)=\max(0,\ \Delta Load(r,t)-AvailableRenewable(r,t))$
- 新增成本：$Cost(i,r,s)=\sum_t GridPurchase(r,t)\times ElectricityPrice(r,t)$
- 新增碳排：$Carbon(i,r,s)=\sum_t GridPurchase(r,t)\times CarbonIntensity(r,t)$
- 新能源收益：$RenewableBenefit(i,r,s)=\sum_t UsedRenewable(r,t)$
- 拥塞惩罚：$Congestion=\max(u_{GPU}(r,t),\ u_{Power}(r,t))$ 或超阈值部分 $\max(0,u-\rho)$ 之和
- GPU/功率利用率：$u_{GPU}=GPU\_Used/Available\_GPU$，$u_{Power}=Total\_Load/Max\_Facility\_Power\_MW$

### 2.5 滚动窗口

- 窗口长度 Δ=24 小时：0-23、24-47、…、2376-2399；窗口 $\tau$ 内任务 $W_\tau=\{i \mid ArrivalHour_i\in[\tau,\tau+\Delta-1]\}$
- 向前看（Lookahead）=72 小时：弹性任务可在未来 72 小时内选开工时间
- 窗口内求解后固定结果，更新 GPU_Used、AI_IT_Load、Total_Load，进入下一窗口

### 2.6 评价指标

- 新能源利用率：$RenewableUtilization=\sum UsedRenewable(r,t) / \sum AvailableRenewable(r,t)$
- 总成本：$TotalCost=\sum GridPurchase(r,t)\times ElectricityPrice(r,t)$
- 总碳排：$TotalCarbon=\sum GridPurchase(r,t)\times CarbonIntensity(r,t)$
- 其他：平均网络时延、任务按时完成率、弃电量、区域 GPU 平均/峰值利用率、系统峰值购电功率

## 三、方法二：多策略 + Pareto 分析

### 3.1 多组权重策略

balanced / cost_first / carbon_first / renewable_first / latency_first / carbon_renewable / cost_carbon / load_balanced，每组一套权重 (α,β,γ,δ,μ)。
示例：综合策略 α=1.0、β=500、γ=2、δ=100、μ=100；成本优先 α↑；低碳优先 β↑；新能源优先 δ↑。

### 3.2 Pareto 支配与前沿

- 目标向量：$z=(Cost,\ Carbon,\ Latency,\ -RenewableUtilization,\ PeakGridPurchase,\ UnassignedCount)$
- A 支配 B：A 所有目标不差于 B 且至少一项更优 → 删除 B
- 剩余非支配方案构成 Pareto 前沿，供决策者选择折中解

## 四、论文中建议的写法（方法一 + 方法二递进）

```
3.1 任务可行域构造
3.2 加权单目标滚动调度模型（方法一，WCRS）
3.3 多策略权重设计
3.4 Pareto 非支配解筛选（方法二）
3.5 不同策略的调度结果比较
```

- 方法一论文命名建议：基于加权单目标的碳感知滚动窗口调度模型（Weighted Carbon-aware Rolling Scheduling, WCRS）
- 方法二论文命名建议：多层启发式 + 多目标 Pareto 分析
- 结论可以强调：不同目标存在冲突，无法同时达到各自最优；Pareto 前沿提供了多种折中方案
